# Ayas

One tiny thing a day, kept where you already look.

An iOS app built around a single loop: see the small action on your Home Screen, do it,
tap once, keep the thread going. The first habit it ships with is reading one Quran ayah
a day, but nothing in the architecture is specific to it.

Requires iOS 17 and Xcode 15 or later.

---

## 1. What is implemented

**App**

- Today screen: the day's habits as hairline-separated rows, each with a completion ring,
  its tiny action, the current streak, and (for ordered habits) today's reference.
- Create and edit habits: name, tiny action, colour, mark, and what the daily content is.
- Habit detail: today's ayah in full, one large control to complete it, current streak,
  best streak, total days, and a fourteen-day strip.
- Settings: appearance, when a new day begins, translation, haptics, erase.
- Empty state that offers the Quran habit in one tap.
- Light and dark mode, both drawn deliberately rather than inverted.

**Widget**

- Home Screen widget in small and medium sizes.
- Shows the habit, today's ayah in Arabic (plus translation on medium), the streak, and
  whether it is done.
- One tap on the ring completes the habit in place, without opening the app.
- Advances to the next day on its own, including clearing the completion and recomputing
  the streak, with no help from the app.
- Each widget is configured with its own habit, so several habits can sit side by side.

**Underneath**

- Full Quran text, 6,236 ayahs, Uthmani script with the Saheeh International translation,
  bundled locally. No network at any point.
- A shared document in an App Group that the app and widget both read and write.
- Streak logic that tolerates missed days, midnight, timezone changes and DST.
- Unit tests for the day, streak, sequence and persistence logic.

codebase this size that is one less moving part, and it keeps the widget's launch cheap.

## 3. How the widget works

`HabitWidget` uses `AppIntentConfiguration`, so each instance carries a `SelectHabitIntent`
naming the habit it shows. Drop three widgets on the Home Screen, long-press each, and
point them at three different habits. If a widget has no selection — or its habit was
deleted — it falls back to the first habit rather than showing an error.

**Completing from the widget.** The ring is a `Button(intent:)` running
`CompleteHabitIntent`. It executes inside the widget extension, writes to the shared
document, and the widget redraws. The app is never launched. The intent is deliberately
one-way: a tap can complete but never un-complete, so a stray thumb on the Home Screen
cannot cost you a streak. Undo lives in the app, where the gesture is intentional.

**Advancing at midnight.** `HabitTimelineProvider` does not emit a single entry. It builds
one entry for now plus one for each of the next four day boundaries, each pre-rendered
with that day's state — completion cleared, next ayah resolved, streak recomputed as it
will stand on that day. WidgetKit swaps entries as each boundary passes, so the widget is
correct tomorrow morning whether or not you have opened the app, and a streak that breaks
over a missed weekend visibly breaks on its own.

Timelines are also refreshed whenever the app writes anything, and when the system reports
a significant time change (midnight, a timezone move).

## 4. Where the Quran data is stored

`Shared/Content/Quran/`, bundled into both targets as a folder reference:

| File | What it is |
| --- | --- |
| `surahs.json` | 114 records: number, Arabic name, transliteration, meaning, revelation place, ayah count |
| `ar.uthmani.txt` | 6,236 ayahs, one per line, UTF-8 |
| `ar.uthmani.idx` | little-endian `UInt32` byte offsets, 6,237 entries |
| `en.sahih.txt` / `.idx` | the same shape for the English translation |

The offset index means fetching one ayah is a `seek` and a short read rather than parsing
a 1.3 MB file — which matters in the widget extension, where memory is tight and only one
ayah is ever needed.

The data was generated once, at build time, from the Tanzil Uthmani text and the Saheeh
International translation via `Tools/build_quran.py`. Nothing is fetched at runtime. The
generator strips the basmalah that the source edition prepends to the first ayah of surahs
2–114, so each record holds exactly its own ayah; surah 1 keeps it, where it genuinely is
ayah 1.

Adding another translation is dropping in a `.txt`/`.idx` pair and registering it in
`QuranLibrary`. No project file change is needed — the folder is a reference.

## 5. Where habit state is stored

One JSON document, `habits.json`, in the App Group container shared by the app and the
widget. It holds every habit, its full completion history, and your settings. There is no
second source of truth, no cache, and nothing derived is persisted — streaks and sequence
positions are computed from the completion history every time they are needed, so they
cannot drift out of step with it.

Both processes read and write it through `NSFileCoordinator`, and every write is atomic.
A document that cannot be decoded is copied aside as `habits-unreadable-<timestamp>.json`
rather than overwritten.

This survives app termination, device restart, widget reloads, and app updates — unknown
enum values and missing keys from another version degrade to sensible defaults instead of
failing the whole document.

If the App Group is misconfigured the app falls back to its own sandbox so it still runs,
and Settings says plainly that the widget cannot stay in step.

## 6. How streak calculation works

A completion is recorded as a **civil day** (`20260928`), never as an instant. Travelling
between timezones therefore cannot move a past completion into a different day.

`currentStreak(asOf:)` walks backwards from an anchor:

- If today is complete, the anchor is today.
- Otherwise, if yesterday is complete, the anchor is yesterday — your streak still reads
  as 6 while today is open and unfinished, rather than dropping to 0 at midnight.
- Otherwise the streak is 0.

From the anchor it counts back one day at a time while each day is present. So three
consecutive days read as 3; missing Wednesday entirely means Thursday's completion starts
a new streak at 1, and the old run is remembered only as the best streak.

Nothing about this depends on the app being opened. The history is the only input, and it
is a pure function of it — which is also why the widget can correctly render a streak for
a day that has not happened yet.

**Day boundaries.** "New day begins at" in Settings shifts the boundary to as late as 4 AM,
so finishing at half past midnight still counts for the night before. The boundary is
computed by comparing the wall-clock hour rather than subtracting hours from an instant —
on a spring-forward morning those are not the same thing, and the naive version puts the
boundary on the wrong side of the date.

**Sequence position** follows completions, not the calendar: miss three days and you still
resume on the next unread ayah rather than skipping three.

## 7. Running it on your iPhone

1. Open `Ayas.xcodeproj` in Xcode.
2. Open `Config/Ayas.xcconfig` and set:
   - `AYAS_BUNDLE_ID_PREFIX` to something you own, e.g. `com.yourname`
   - `AYAS_APP_GROUP` to `group.<that prefix>.shared`
3. Select the **Ayas** target → Signing & Capabilities → pick your Team. Repeat for the
   **AyasWidgetExtension** target. Both need the same team.
4. On each of those two targets, confirm the **App Groups** capability lists the group from
   step 2, and that it is ticked. Xcode will register it with your account.
5. Plug in your iPhone, select it as the run destination, and press Run.
6. First launch on a device: Settings → General → VPN & Device Management → trust your
   developer certificate.
7. Add the widget: long-press the Home Screen → **+** → search "Ayas" → pick a size. To
   point it at a different habit, long-press the widget → Edit Widget.

Run the tests with ⌘U.

## 8. Setup and signing requirements

- **Xcode 15+**, iOS 17+ device or simulator.
- **A signing team.** A free Apple ID works; app group registration is supported.
- **The App Group must match** in three places, all fed from `Config/Ayas.xcconfig`: both
  entitlements files and both Info.plists read `$(AYAS_APP_GROUP)`, and `AppGroup.swift`
  reads it back at runtime. Change it in the xcconfig only.
- **Widget bundle ID must stay prefixed by the app's.** It is set to
  `$(AYAS_BUNDLE_ID_PREFIX).Ayas.widget` and should keep that shape.
- Interactive widget buttons need iOS 17 on the device. On iOS 16 the widget would render
  but not respond to taps — the deployment target rules that out.

If you add or remove a source file, regenerate the project:

```
python3 Tools/generate_xcodeproj.py
```

## 9. Known limitations

- **Not compiled.** This was written on Windows, where no Swift or iOS toolchain exists, so
  it has never been through a compiler or run on a device. The project file is generated
  from the file tree rather than hand-written, and the logic is covered by unit tests, but
  expect to fix a small number of compile errors on first build.
- **Daily only.** No weekly or n-times-a-week rhythms; the editor says so plainly.
- **Today only.** You can complete or undo today, but not backfill a day you forgot.
- **Two widget sizes.** Small and medium. Lock Screen accessory families are not included;
  `Metrics` in `HabitWidgetView` is where a new family would be added.
- **Widget interaction is one-way.** Completing from the widget cannot be undone there.
- **Timezone edge.** Pre-rendered widget entries are computed in the timezone that was
  current when the timeline was built. A flight across zones leaves the widget briefly
  stale until iOS reports the time change or the app is opened; the app itself is correct
  immediately.
- **No notifications, accounts, sync or analytics.** Deliberately.
- **Quran translation is English only**, and the data layout is the extension point for
  more.
